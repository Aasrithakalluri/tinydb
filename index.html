Open decisions

decision Escalation policy: when must a run reach a human? The experiments give four concrete candidates: (1) a pull request that removes assertions from existing tests (a detector would have flagged exactly one of eight real PRs, #14, and no harmless one); (2) a design that lists a change that was never applied, or records an unresolved conflict, yet the run is reported DONE (seen in Experiment 1, issue 2); (3) ambiguity that changes behaviour (a P1 question plus an ASSUMED item in an acceptance criterion); (4) the reviewer rejecting the approach twice. A naive "any P1 question" rule would stall most runs (Haiku marks even clear issues NOT READY). Not implemented; it would become ADR-015.

done Hidden-test validity: validated with a reference fix and an independent alternative fix per issue (experiment/validation/); issue 5's answer-based tests were written before its ask-mode run resumed; issue 2 is a documented contract conflict, scored with a second measure. The tests are now released in experiment/hidden_tests/ and match the manifest committed before the runs.

Findings so far (raw material for the report)

  1. Invalid workflow YAML (runner context in job env) was found only on push, and fixed with actionlint.
  2. The repo setting "Allow GitHub Actions to create pull requests" had to be enabled.
  3. Restart bug (ADR-004 superseded by ADR-011): restoring state.json did not restore the code. An empty commit was force-pushed and PR #10 briefly had 0 changes. A reasoned ADR was falsified by one real run.
  4. The CI wait matched a gated pull_request run (action_required). It now uses the workflow_dispatch run.
  5. Lint false rejection (ADR-012): tagged criteria such as FR-03-AC1 (failure): were invisible to my regex, so a correct spec for #4 failed stage 1.
  6. Vague issue: with no human available, the Planner wrote "do not implement until Q-01 is resolved" and the Builder produced an empty diff. This led to assume mode (ADR-012) and ask mode (ADR-013).
  7. Assume-mode guess approved by the reviewer (#5): the reviewer does not see the spec, so it cannot challenge an ASSUMED interpretation. Hidden tests 2/3.
  8. The design lint caught a real error: the Planner named a test symbol that did not exist (#3, #5), and the retry fixed it.
  9. Reviewer quality: it ran the suite and its own experiments and checked constraints 4 and 5. For #2 it noticed that the ADR-3 wording in ARCHITECTURE.md is now stale.
  10. Wrong artifact restored: the artifacts API lists by id, not creation time, so /autose go restored a finished run's state and did nothing. Fixed by sorting on created_at (ADR-011 addendum).
  11. Red master CI: the repo's pytest collected workflow/tests/; every CI job failed from PR #22 on. Fixed with testpaths = tests; restart now rebases onto the current default branch.
  12. Ask vs assume (#5): the same hidden-test score (5/6), lower cost when asking ($0.092 vs $0.163). One issue, and the answers were mine, so a null result with caveats.
  13. Prompt injection resisted (one direct attack): the Planner recorded it as a risk, the reviewer ignored it and still tested. All denied tool calls were benign formatting (&& echo OK, | tail).
  14. Budget cap left an unreviewed PR looking finished; now the orchestrator comments on the PR when a run stops early.
  15. A fake failure caused churn: the diff grew from 18 to 201 lines when the Builder was told tests failed although they had not.
  16. Issue #2 asks to break a documented, tested contract (Table.search docstring and test_query_cache_documents_are_shared_with_cache). The pipeline rewrote that test and the reviewer approved; any valid fix must change it. Only 1 of 8 PRs removed assertions from existing tests.
  17. Independence did not buy detection (Exp 2): the independent Sonnet reviewer missed the one defect class where the issue is silent but sibling code and the author's spec are not (S4); Haiku with the spec caught it. Independence is kept (assignment rule); ADR-014 adds a compare-with-siblings step. Neither reviewer escalated the reversal of a documented contract.
  18. An experiment driver bug cost $0.42: Experiment 1 wrote its artifacts inside the repository, the orchestrator staged and rejected them, and every one of 20 runs failed on its own files while the agents' real work was fine. The offline test had used an output folder outside the repo. Fixed with a guard that refuses an output folder inside the repo; the invalid run is logged, no result taken from it.
  19. The API credit ran out before our own tracker said it would: Experiment 1 got "Credit balance is too low" on 18 of 20 runs. Either the credit was below $5 or the orchestrator's cost estimate undercounts (it sums the SDK's reported cost per call); the console is authoritative. No result was invented for those runs.
  20. ADR-014 test (pre-registered): the compare-with-siblings prompt fixed S4 and routed the documented-rule reversal to approach, but falsely rejected a correct control twice; the old prompt already caught the two new seeds, so they did not discriminate. Stays Proposed; production prompt unchanged.
  21. My tooling hid its own failure: a stale local branch was pushed instead of the new seed commit and the build output filtered out the error, so S3 was reviewed against the wrong defect. Fixed with an explicit HEAD:refs/heads/... push, visible errors, and a runner guard that compares each branch diff with its patch file. The invalid reviews are kept and flagged.
  22. Two confounds found in my own experiment design (variant B given artifacts of different code; v2 mutations that made the PR's own suite fail) and removed before the main result, with the pilot kept as evidence.
  23. Experiment 1 (one agent vs three, 20 runs): no quality difference attributable to the split (10/10 vs 9/10 excluding the extra test), and the split costs about 70% more per run ($0.0202 vs $0.0118). The single agent's one miss was a deliberate non-fix of issue #2 (it recognised the conflict with a documented contract and wrote xfail tests), which the pipeline reported as DONE: a listed change need not be applied, and xfail hides an unresolved conflict. In 3 of 4 issue-2 runs the agents rewrote the contract test instead.
  24. Back-edges verified for real (fault-injected and labelled, $0.128): tests failing three times led to two retries and then a redesign; a simulated reviewer "changes" verdict sent the run back to the Builder; it finished DONE after a second review. After simulated failures the Builder inflated the diff (191 and 164 lines against 40 after the redesign).
  25. Hidden tests were released only after the last agent run on issues 1 to 5, with a SHA-256 manifest committed before the runs, so the agents could not have read them.
  26. Cost is small: about $0.06 to $0.09 per clean run. The vague issue costs 2 to 3 times more.
